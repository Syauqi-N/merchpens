# Next.js 16.2.12 — Conventions & Breaking-Changes Cheat Sheet

Digested from the **bundled** docs at `node_modules/next/dist/docs/`. This is NOT the Next.js in your training data. When in doubt, read the bundled markdown, not your memory.

> Scope: App Router, production e-commerce. Every section cites the source doc.

---

## 0. TL;DR — the things that break if you code from memory

- All request APIs are **async Promises**: `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()`. Sync access was fully **removed** in v16.
- `fetch()` is **NOT cached by default** (uncached/dynamic). Opposite of Next 13/14.
- `middleware.ts` is renamed to **`proxy.ts`** (function `proxy`, runtime is **nodejs only** — no edge).
- `revalidateTag('tag')` now **requires a second arg**: `revalidateTag('tag', 'max')`.
- Caching is opt-in via **Cache Components** (`cacheComponents: true`) + the **`use cache`** directive. `cacheLife`/`cacheTag` are now stable (drop `unstable_`).
- `error.tsx` boundary prop is **`unstable_retry`**, not `reset`.
- Turbopack is the **default** builder; a stray `webpack` config makes `next build` fail.
- `next lint`, `serverRuntimeConfig`/`publicRuntimeConfig`, and AMP are **removed**. `images.domains` is deprecated (use `remotePatterns`).

## 1. Async Dynamic APIs (BREAKING)
Source: `01-app/02-guides/upgrading/version-16.md`, `01-app/01-getting-started/03-layouts-and-pages.md`, `route.md`

In v16, synchronous access to request-time APIs is **fully removed**. `params`, `searchParams`, `cookies()`, `headers()`, and `draftMode()` are all `Promise`s and must be awaited.

**Page** (`params` + `searchParams` are Promises):

```tsx
// app/products/[slug]/page.tsx
export default async function Page({
  params,
  searchParams,
}: {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const { slug } = await params
  const { sort } = await searchParams
  // ...
}
```

**Layout** (`params` is a Promise; layouts have NO `searchParams`):

```tsx
// app/products/[slug]/layout.tsx
export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  return <section>{children}</section>
}
```

**cookies / headers / draftMode** (async, from `next/headers`):

```tsx
import { cookies, headers, draftMode } from 'next/headers'

const cookieStore = await cookies()
const theme = cookieStore.get('theme')?.value
const h = await headers()
const ua = h.get('user-agent')
const { isEnabled } = await draftMode()
```

- Reading `searchParams`, `cookies()`, or `headers()` opts the route into **dynamic rendering**.
- Typed helpers are globally available (generated by `next dev`/`next build`/`next typegen`): `PageProps<'/products/[slug]'>`, `LayoutProps<'/products'>`, `RouteContext<'/users/[id]'>`. No import needed.
- Also breaking: `opengraph-image`/`icon`/`apple-icon` image fns receive `params` and `id` as Promises; `sitemap` receives `id` as a Promise.

## 2. Server vs Client Components
Source: `01-app/01-getting-started/05-server-and-client-components.md`

- **Default = Server Component.** Layouts and pages are Server Components unless marked otherwise.
- Add `'use client'` at the **top of the file, above imports** to make a Client Component. It declares a boundary: every import and directly-rendered child of that file joins the client bundle.
- Data fetching belongs in **Server Components** (DB/ORM/`fetch` with secrets). Put `'use client'` only on the interactive leaf (button, search box), not whole layouts.
- Server Components passed as `children`/props into a Client Component still render on the server (interleaving pattern) — use this for `<Modal><Cart/></Modal>`.
- React Context is **not** available in Server Components; wrap providers in a `'use client'` component and render as deep as possible.
- Secret hygiene: only `NEXT_PUBLIC_`-prefixed env vars reach the client; use the `server-only` package to hard-fail accidental client imports.

## 3. Data Fetching in Server Components
Source: `01-app/01-getting-started/06-fetching-data.md`

- Make the component `async` and `await` the I/O (`fetch`, ORM, DB client).

```tsx
export default async function Page() {
  const data = await fetch('https://api.example.com/products') // NOT cached by default
  const products = await data.json()
  // ...
}
```

- **`fetch` is NOT cached by default** and blocks render until complete. Identical `fetch` calls in one render tree are **memoized** (deduped per request), not persistently cached.
- To cache: use the `use cache` directive (see §5). To keep fresh but non-blocking: wrap the component in `<Suspense>` to stream.
- **Client Component fetching**: React `use()` API (pass a Promise from a Server Component and read it with `use()` inside `<Suspense>`), or SWR / React Query.
- Parallel fetch: kick off `fetch` calls, then `await Promise.all([...])`. Share per-request data with `React.cache(async () => ...)`.

## 4. Mutating Data — Server Actions / Server Functions
Source: `01-app/01-getting-started/07-mutating-data.md`, `01-app/01-getting-started/09-revalidating.md`

Server Function = async fn with `'use server'` (top of fn body, or top of file to mark all exports). In a form/action context it's a "Server Action". Invoked via `POST` only.

```ts
// app/lib/actions.ts
'use server'

import { auth } from '@/lib/auth'
import { revalidatePath, revalidateTag, updateTag, refresh } from 'next/cache'
import { redirect } from 'next/navigation'
import { cookies } from 'next/headers'

export async function createProduct(formData: FormData) {
  const session = await auth()
  if (!session?.user) throw new Error('Unauthorized') // always authz inside the action
  const title = formData.get('title')
  // ...mutate...
  revalidatePath('/products')
  redirect('/products')
}
```

Form usage (progressive enhancement works without JS):

```tsx
import { createProduct } from '@/app/lib/actions'
export function Form() {
  return (
    <form action={createProduct}>
      <input name="title" />
      <button type="submit">Create</button>
    </form>
  )
}
```

- **Cannot** define Server Functions inside Client Components — import them from a `'use server'` file and use via `action`, `formAction`, `onClick`, or `useEffect`.
- Pending state: `const [state, action, pending] = useActionState(fn, initial)`.
- Expected errors: **return** a value (e.g. `{ message }`) and read it via `useActionState`; don't throw for validation.
- Cache invalidation from an action:
  - `revalidatePath('/path')` — invalidate a route.
  - `revalidateTag('tag', 'max')` — **second arg (cacheLife profile) is now required**; stale-while-revalidate. Works in Actions AND Route Handlers.
  - `updateTag('tag')` — **Server Actions only**; expires immediately (read-your-own-writes).
  - `refresh()` — refreshes the client router only (does not revalidate tagged data).
- Cookies get/set/delete inside an action re-render the current tree so UI reflects the new value.

## 5. Caching Model — Cache Components & `use cache`
Source: `01-app/01-getting-started/08-caching.md`, `09-revalidating.md`, `02-guides/caching-without-cache-components.md`, `version-16.md`

**Yes, there is a `use cache` directive and a Cache Components model.** Two worlds:

### A) Cache Components (recommended, opt-in)
Enable in config:

```ts
// next.config.ts
import type { NextConfig } from 'next'
const nextConfig: NextConfig = { cacheComponents: true }
export default nextConfig
```

- `'use cache'` caches an async function's return **or** a whole component/page/layout. Args + closed-over values form the cache key.

```tsx
import { cacheLife, cacheTag } from 'next/cache' // stable now — no unstable_ prefix

async function getProducts() {
  'use cache'
  cacheLife('hours')       // profiles: seconds|minutes|hours|days|weeks|max|default
  cacheTag('products')
  return db.query('SELECT * FROM products')
}
```

- **Not** cached and needs fresh data? Do **not** add `use cache`; wrap in `<Suspense>` to stream at request time.
- Runtime APIs (`cookies`, `headers`, `searchParams`, uncached `params`) must sit inside a `<Suspense>` boundary or you get a build error: *"Uncached data was accessed outside of `<Suspense>`."*
- Non-deterministic ops (`Math.random`, `Date.now`, `crypto.randomUUID`) require `await connection()` (from `next/server`) before them, or must be inside `use cache`.
- Default rendering with Cache Components = **Partial Prerendering (PPR)**: static shell + streamed dynamic holes. (`experimental.ppr` and `experimental_ppr` segment config are removed; use `cacheComponents`.)
- `use cache` **cannot** be placed directly in a Route Handler body — extract to a helper.

### B) Previous model (no Cache Components)
Source: `02-guides/caching-without-cache-components.md`

- `fetch` uncached by default; opt in per call: `fetch(url, { cache: 'force-cache' })`.
- `unstable_cache` **still exists** for caching non-`fetch` functions:
  ```ts
  import { unstable_cache } from 'next/cache'
  export const getUser = unstable_cache(async (id) => db.user(id), ['user'], { revalidate: 3600, tags: ['user'] })
  ```
- **Route segment config** (pages/layouts/route handlers): `export const dynamic = 'auto' | 'force-dynamic' | 'force-static' | 'error'`; `export const revalidate = false | 0 | number`; `export const fetchCache`, `runtime`, `dynamicParams`, `preferredRegion`.

## 6. Route Handlers (`app/**/route.ts`)
Source: `01-app/01-getting-started/15-route-handlers.md`, `03-api-reference/03-file-conventions/route.md`

Exact export signature — one function per HTTP verb:

```ts
// app/api/webhook/route.ts
import type { NextRequest } from 'next/server'

export async function GET(request: NextRequest) { /* ... */ }
export async function POST(request: NextRequest) { /* ... */ }
// Also: PUT, PATCH, DELETE, HEAD, OPTIONS
```

- **Not cached by default.** Opt a `GET` into caching with `export const dynamic = 'force-static'`. Other verbs are never cached.
- A `route.ts` and a `page.ts` **cannot** coexist at the same segment.
- Dynamic params are a Promise: `export async function GET(req, { params }: { params: Promise<{ id: string }> }) { const { id } = await params }`. Or type ctx with `RouteContext<'/users/[id]'>`.

### Reading a `application/x-www-form-urlencoded` body (Duitku webhook)
`request.formData()` parses BOTH `multipart/form-data` and `application/x-www-form-urlencoded`. No `bodyParser` config needed (unlike Pages API routes).

```ts
// app/api/payment/duitku/callback/route.ts
export async function POST(request: Request) {
  const form = await request.formData()
  const merchantOrderId = form.get('merchantOrderId')?.toString()
  const amount = form.get('amount')?.toString()
  const signature = form.get('signature')?.toString()
  const resultCode = form.get('resultCode')?.toString()

  // ...verify signature, update order...

  return new Response('OK', { status: 200 }) // Duitku expects a plain 200
}
```

### Reading the RAW body (for HMAC/signature verification)
```ts
export async function POST(request: Request) {
  const raw = await request.text() // raw string body
  // verify signature over `raw`, then parse:
  const params = new URLSearchParams(raw) // for x-www-form-urlencoded
  const orderId = params.get('merchantOrderId')
  return new Response('OK', { status: 200 })
}
```
> A request body can only be consumed **once** — pick `request.text()` OR `request.formData()` OR `request.json()`, not several.

### Returning a plain 200 text response
```ts
return new Response('OK', { status: 200 })           // text
return new Response('Success!', { status: 200 })     // webhook ack
return Response.json({ ok: true })                   // JSON helper
```

Read query params via `request.nextUrl.searchParams`. Read cookies via `request.cookies.get('x')` or `await cookies()`.

## 7. Proxy (formerly Middleware) — BREAKING RENAME
Source: `01-app/01-getting-started/16-proxy.md`, `03-api-reference/03-file-conventions/proxy.md`, `version-16.md`, `02-guides/authentication.md`

> Since v16, **Middleware is renamed to Proxy**. `mv middleware.ts proxy.ts` and rename the function to `proxy`.

- File: single `proxy.ts` (or `.js`) at project root (or `src/`), sibling to `app`.
- Runtime is **`nodejs` and cannot be configured** — the **`edge` runtime is NOT supported** in `proxy`. If you need edge, you must keep `middleware` (deprecated).
- `fetch` cache options (`cache`, `next.revalidate`, `next.tags`) have **no effect** inside proxy.
- Renamed config flags, e.g. `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`.

Protecting an `/admin` area:

```ts
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { cookies } from 'next/headers'
import { decrypt } from '@/app/lib/session'

export async function proxy(req: NextRequest) {
  const path = req.nextUrl.pathname
  const cookie = (await cookies()).get('session')?.value
  const session = await decrypt(cookie)

  if (path.startsWith('/admin') && session?.role !== 'admin') {
    return NextResponse.redirect(new URL('/login', req.nextUrl))
  }
  return NextResponse.next()
}

// Run everywhere except assets/api/images:
export const config = {
  matcher: ['/((?!api|_next/static|_next/image|.*\\.png$).*)'],
}
```

- `matcher` accepts a string, an array of strings (`['/admin/:path*', '/dashboard/:path*']`), a regex-style negative lookahead, or objects `{ source, locale?, has?, missing? }`.
- Without a `matcher`, proxy runs on **every** request (including static assets) — always scope it.
- Use proxy only for **optimistic** cookie-based checks (it runs on prefetches too). Do real authz in a Data Access Layer near the data.

## 8. Metadata API
Source: `01-app/01-getting-started/14-metadata-and-og-images.md`

- Only in **Server Components**. Static object or dynamic function.

```tsx
// Static
import type { Metadata } from 'next'
export const metadata: Metadata = { title: 'Shop', description: '...' }
```

```tsx
// Dynamic — params/searchParams are Promises
export async function generateMetadata(
  { params }: { params: Promise<{ slug: string }> }
): Promise<Metadata> {
  const { slug } = await params
  const product = await getProduct(slug) // wrap getProduct in React cache() to dedupe with the page
  return { title: product.title, description: product.description }
}
```

- Dynamic pages **stream** metadata (injected once resolved), except for known bots. Prerendered pages resolve metadata at build time.
- File conventions: `favicon.ico`, `opengraph-image.jpg`/`.tsx`, `twitter-image`, `robots.txt`, `sitemap.xml`. Dynamic OG images via `ImageResponse` from **`next/og`** (`export const size`, `contentType`; flexbox subset of CSS only, no grid).

## 9. next/image, next/font, next.config.ts images
Source: `01-app/01-getting-started/12-images.md`, `13-fonts.md`, `version-16.md`

**next/image**
```tsx
import Image from 'next/image'
<Image src="/profile.png" alt="..." width={500} height={500} />          // local, explicit size
import Pic from './pic.png'; <Image src={Pic} alt="..." />               // static import auto-sizes + blur
<Image src="https://cdn.example.com/a.png" alt="..." width={500} height={500} /> // remote needs w/h + config
```

`images.remotePatterns` shape (object entries):
```ts
// next.config.ts
const config: NextConfig = {
  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 's3.amazonaws.com', port: '', pathname: '/my-bucket/**', search: '' },
    ],
  },
}
```

v16 image breaking defaults to know:
- `images.domains` is **deprecated** → use `remotePatterns`.
- `qualities` default is now **`[75]`** only (add others explicitly).
- `minimumCacheTTL` default `60s` → **4 hours (14400s)**.
- `imageSizes` no longer includes `16`.
- Local images with query strings need `images.localPatterns[].search`.
- Local-IP optimization blocked unless `images.dangerouslyAllowLocalIP: true`.
- `maximumRedirects` default is now `3`.
- `next/legacy/image` is deprecated → `next/image`.

**next/font** (self-hosted, zero external requests, no layout shift)
```tsx
import { Geist } from 'next/font/google'
const geist = Geist({ subsets: ['latin'] })            // variable font: no weight needed
export default function RootLayout({ children }) {
  return <html lang="en" className={geist.className}><body>{children}</body></html>
}
```
Non-variable fonts need `weight: '400'`. Local: `import localFont from 'next/font/local'; localFont({ src: './my-font.woff2' })` (path relative to the file; `src` can be an array for multiple weights/styles).

## 10. Removed / Renamed / Deprecated (upgrading guide)
Source: `01-app/01-getting-started/18-upgrading.md`, `02-guides/upgrading/version-16.md`

**Removed:**
- Synchronous `params`/`searchParams`/`cookies`/`headers`/`draftMode` access.
- `next lint` command (use ESLint/Biome directly; `next build` no longer lints). `eslint` config option removed.
- `serverRuntimeConfig` & `publicRuntimeConfig` (use `process.env` / `NEXT_PUBLIC_`; call `await connection()` before `process.env` to force runtime reads).
- AMP (`next/amp`, `useAmp`, `amp` config).
- `unstable_rootParams`.
- `experimental_ppr` segment config and `experimental.ppr`.
- `devIndicators.appIsrStatus`/`buildActivity`/`buildActivityPosition`.
- `size` & `First Load JS` columns from `next build` output.

**Renamed:**
- `middleware.ts` → **`proxy.ts`** (function `middleware` → `proxy`); config flags e.g. `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`.
- `experimental.turbopack` → top-level `turbopack`.
- `unstable_cacheLife`/`unstable_cacheTag` → **`cacheLife`/`cacheTag`** (stable).
- `revalidateTag(tag)` → **`revalidateTag(tag, profile)`** (second arg required).

**Deprecated:**
- `images.domains`, `next/legacy/image`.
- `experimental.dynamicIO` & `experimental.useCache` → top-level `cacheComponents`.
- `middleware` convention itself (kept only for edge-runtime holdouts).

**Behavioral changes:**
- **Turbopack is default** for `next dev` and `next build`; a `webpack` config makes `next build` fail (use `--webpack` to opt out).
- React **19.2** (canary features: View Transitions, `useEffectEvent`, Activity).
- Node **20.9+**, TypeScript **5.1+** required.
- Every **parallel-route slot needs a `default.js`** or the build fails.
- Next no longer overrides `scroll-behavior: smooth` unless you set `data-scroll-behavior="smooth"` on `<html>`.
- `next dev` outputs to `.next/dev` (concurrent dev+build); `process.argv` no longer contains `'dev'`.

## Bonus: Error Handling deltas
Source: `01-app/01-getting-started/10-error-handling.md`

- `error.tsx` / `global-error.tsx` must be `'use client'`; the recovery prop is **`unstable_retry`** (not `reset`): `({ error, unstable_retry }) => ...`.
- Component-level boundaries: `unstable_catchError as catchError` from **`next/error`**.
- `global-error.tsx` must render its own `<html>`/`<body>`.
- `notFound()` / `redirect()` from `next/navigation`; `redirect()` throws a control-flow exception (code after it never runs).
